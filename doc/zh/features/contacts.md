# 联系人

联系人是 Bonds 的核心实体。每个联系人都属于一个 [Vault](/zh/features/vaults)，可以存储关于某个人的丰富结构化信息。

## 联系人信息

每个联系人支持：

- **姓名**：名、姓、昵称、曾用名。
- **联系方式**：邮箱、电话、社交媒体链接（12 种内置类型）。
- **地址**：多个地址，支持类型标记（家庭、工作等），可选地理编码。
- **公司**：职位和公司关联。
- **性别与代词**：可自定义的性别和代词选项。
- **宗教**：可选的宗教信仰。
- **需要验证标记**：可将联系人标记为「需要验证」。当某些人的联系方式可能过期时，这是一个极佳的视觉提醒，便于你定期核对与确认。

## 模块

联系人详情页默认以**查看模式**打开，优先展示已填写、适合阅读的信息，包括摘要字段、快速信息和笔记，不显示编辑控件。切换到**编辑模式**后，可进入完整模板标签页并使用各模块的增删改功能。

联系人编辑页由**模块**组成，也就是显示在模板页面上的可配置组件。默认模块包括：

| 模块 | 说明 |
|------|------|
| 联系人姓名 | 姓名字段和昵称 |
| 重要日期 | 生日、纪念日、自定义日期 |
| 关系 | 家人、伴侣、朋友 |
| 笔记 | 附加到联系人的自由文本 |
| 任务 | 关联到联系人的待办事项 |
| 提醒 | 定时通知 |
| 通话 | 电话记录及备注 |
| 礼物 | 礼物想法和追踪 |
| 借贷 | 借入或借出的钱款或物品，支持数量、借出/借入日期、归还期限和归还状态 |
| 活动记录 | 重要活动与里程碑，可关联同一 Vault 内的其他参与联系人 |
| 宠物 | 宠物名称和类别（类别在账户层面统一管理） |
| 分组 | 联系人分组归属 |
| 文档 | 上传的文件（PDF、图片） |
| 媒体 | 照片和视频画廊 |
| 日记 | 带模板的日记式条目 |
| 目标 | 个人目标追踪 |
| 动态 | 活动时间线 |

## 模板

模板控制联系人详情页的布局。每个模板有多个**页面**（标签页），每个页面显示一组模块。默认模板包含：

1. **联系信息**：头像、姓名、重要日期、性别、标签、公司、宗教。
2. **动态**：活动时间线。
3. **社交**：关系、宠物、分组、地址、联系方式。
4. **活动记录**：重要活动与里程碑。
5. **目标**：个人目标与进度。
6. **信息**：文档、媒体、笔记、提醒、借贷、任务、通话、日记。

模板和模块分配可通过[个性化设置](/zh/features/admin#个性化设置)自定义。

## 标签

标签是你可以分配给联系人的标记，用于组织和筛选。创建自定义标签，按你喜欢的方式分类联系人。

## 头像

每个联系人都有头像。如果没有上传照片，Bonds 会自动生成**首字母头像**，也就是一个带有联系人首字母的彩色圆形。颜色由名字的 MD5 哈希确定性生成，同一个名字始终得到相同的颜色。

## 宠物

你可以为联系人添加宠物。宠物类别在账户级别定义，允许你从预定义的类别列表（例如狗、猫或鸟）中进行选择。你可以通过系统设置中的“个性化设置”来管理这些宠物类别。

## 按身份反查联系人（by-identity）

集成应用和 AI 助手经常需要回答「这个邮箱/电话号属于哪个联系人？」，而不希望遍历整个 Vault 做字符串匹配。

Bonds 提供 vault 范围的反查端点：

```
GET /api/vaults/{vault_id}/contactInformation/by-identity?data=<value>&type_id=<n>
```

- `data`（必填）：要查找的身份值，匹配**大小写不敏感**。
- `type_id`（可选）：限定只在某种 `ContactInformationType`（例如只查邮箱）中查找。

响应是一组匹配，每条包含 `contact_id`、联系人姓名以及完整的 `ContactInformationResponse`。查找仅限单个 vault，要求对该 vault 至少拥有 Viewer 权限。

示例：

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "$APP_URL/api/vaults/$VAULT_ID/contactInformation/by-identity?data=alice@example.com"
```

## 关系

定义联系人之间的关系，包括父母、子女、伴侣、朋友、同事等。关系类型按组分类：

- **爱情**：伴侣、配偶、恋人。
- **家庭**：父母、子女、兄弟姐妹。
- **友谊**：密友、熟人。
- **工作**：同事、导师、上司。

### 跨 Vault 关系

关系可以跨越不同的 Vault。添加关系时，联系人选择器会显示你有权访问的**所有 Vault** 中的联系人，按 Vault 名称分组。

- 若你对目标 Vault 拥有**编辑者**权限，系统会自动创建**双向关系**（两个联系人都能看到该关系）。
- 若你只有**查看者**权限，则只创建**单向关系**，界面会提示原因。
- 删除跨 Vault 关系时，会自动清理对方的反向记录。

## 合并重复联系人

在同一空间选中 2–50 个联系人，点击**合并联系人**。先选择保留身份、可见性及布局的目标。预览显示所有非空资料值、冲突、重要日期和受影响记录数量；逐项选择冲突值并确认实际影响。预览后资料发生变化需重新审核。编辑者和管理员可操作，受保护联系人只能作为保留目标。

空字段自动补齐，公司与职位、初次见面日期各部分整体保留。笔记、电话、地址、文件、工作、任务、活动及提醒原位迁移，不删除内容相似的独立记录。相同成员关联及关系会归并，所选联系人间的关系因合并为自身关系而移除。额外生日／忌日转为普通日期，保留提醒 ID 及调度时间。群组角色冲突及当前空间无法访问的旧介绍人引用需先处理。迁移入向关系和介绍人引用必须拥有**每个引用所属空间**的编辑权限。

不复制来源资料到笔记，不新增快照或撤销表。经明确确认后，未选中的单值字段从有效资料舍弃。来源沿用已有软删除生命周期，审计动态仅记录合并数量。操作不可撤销。Monica 重导入跳过已删除来源 UUID；vCard 文件导入仍只新增，再次导入可能产生重复项，但不会覆盖已合并联系人。

已关联 CardDAV 的联系人不可合并，包括停用、只读订阅及旧远端路径：后续拉取可能覆盖合并字段，远端删除也无法与本地事务保持原子性。请先在远端来源合并。即使联系人尚未关联，空间有启用的 DAV 推送时也需先暂停推送。未处理的原始 vCard 资料需先处理。确认时会重新校验这些限制，不删除远端记录或同步映射。

对于 Bonds 自身的 CardDAV 通讯录，已删除来源路径不可读取，也拒绝旧客户端回写。目标更新会校验请求中的 ETag，过期的条件写入不会覆盖合并结果。主动省略条件的客户端仍采用标准的无条件更新行为。

DAV 往返时，未变动的电话、地址和日期保留原记录及元数据。会替换现有日期、带类型的联系信息、共享／历史／详细地址的操作返回冲突，请通过 Bonds 编辑，避免破坏合并后的提醒引用和地址历史。
